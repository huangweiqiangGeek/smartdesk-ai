## 1 使用方法与开发执行流程

获得后续开发指令后，将第 2 节通用提示词与一个对应任务提示词一起交给 Codex。先执行开发任务 T01；一项完成后依据真实记录进入下一项，不一次要求“把全部功能做完”。本包不表示任务已启动，不会自动创建 Agent 或发布项目。

任务 ID 在这里均指 task:T01—task:T26；PRD 工单需求 requirement:T01—requirement:T04 是另一套编号。实际版本、路径和命令以初始化后的仓库为准，规划路径不能作为存在证据。

~~~mermaid
flowchart TD
    D1[读取当前任务与必要文档] --> D2[检查实际工程和前置任务证据]
    D2 --> D3[列出本项交付与验收方式]
    D3 --> D4[核对公共合同和关键失败场景]
    D4 --> D5[分小步实现当前任务]
    D5 --> D6[运行受影响验证]
    D6 -->|失败| D5
    D6 -->|通过| D7[同步合同和任务记录]
    D7 --> D8[清理验证服务并交付结果]
~~~

实现和验证由同一任务串行维护共享文件。依赖缺失时先说明实际缺项；不能绕过缺项完成一个只在 mock 中成立的页面。只有新发现涉及产品范围、业务规则或不可替代外部配置的决策才需要向用户澄清；已明确授权的常规实现持续完成。

## 2 通用提示词

~~~text
你正在实施 SmartDesk AI V1 的一个开发任务。请把下面的任务段与本段作为完整工作单。

先读取项目 AGENTS.md、docs/README.md、docs/prd-v1.md 中相关模块，以及本任务引用的设计；根据需要读取 technical-plan-v1.md、data-model-v1.md、api-v1.md、pages-v1.md、ai-workflow-v1.md。需求以 PRD 为准，公共枚举/envelope/预算以 contracts.md 为准，详细合同与消费者保持同步。

先检查实际目录和任务记录；如存在 Git，检查分支、HEAD、status 和相关 diff。保护用户已有修改，不自动撤销、提交、推送、发布，不自动创建其他 Agent。新增/升级依赖先核查当前官方文档，再锁定兼容版本，不照抄不匹配版本的 API。

仅实现下面指定的开发任务 T 编号。核对 development-tasks-v1.md 中的前置任务和验收，先给出简短计划、假设和验证方法，再进行增量修改。设计中的 app 路径若尚不存在，按任务建立最小结构；不得把不存在的接口或模型能力当成已可用。发现文档冲突先指出精确位置；普通实现细节按既定设计解决，不能暗中扩大 PRD。

保持八模块和五条业务规则：AI 先接待；必要时转人工；服务端接受交接后禁止自动回复；离线消息可靠保存；会话和工单独立。HTTP/Socket 共用业务服务，服务端做身份与资源授权，消息同 ID 重试只产生一个效果。不要先实现 PDF 导入、渠道集成、自动派单、多 Agent、支付或外部业务执行。

只为实际风险建立有意义的测试，验证数据库效果、权限、状态和界面行为，不用镜像实现的断言或 mock 调用次数代替业务证据。没有真实 AI 配置时可完成可控替身验证，但清楚记录真实模型未验证，不据此宣称 V1 完成。

完成后同步本任务直接影响的合同/说明和任务状态。汇报：实现结果与文件；对应需求/验收；实际命令、cwd、退出码和环境；真实与模拟边界；未完成项及下一个可启动任务。没有执行的测试明确写未执行。记录并停止仅由你启动的验证服务，确认端口释放；不停止用户原有服务。不自动执行下一个任务。
~~~

## 3 T01—T26 任务提示词

### T01 工程、版本和本地环境

~~~text
执行开发任务 T01。读 technical-plan-v1.md 第 5/13/20/22 节及 quality.md。
建立最小 pnpm workspace、Nuxt 4/Vue 前端、NestJS API/worker 入口、FastAPI 内部服务；准备 PostgreSQL+pgvector 与 Redis 的本地依赖运行方式。应用目录、数据库 schema/迁移目录与共享包遵循现有约束，不额外拆业务微服务。
用当前官方资料核对 Node/Python、Nuxt/Nest/Prisma/pgvector 等兼容版本，记录并锁定实际安装结果。模型与 Embedding 的 modelId、维度和 Token 预算形成明确配置合同；缺真实配置时仅提供可控替身，不编造真实能力验证。
验收：最小启动/健康检查、数据库连接及已有静态检查实际通过；记录命令和退出码，不实现聊天假数据闭环。清理本任务启动的进程。
~~~

### T02 数据模型与迁移约束

~~~text
执行开发任务 T02，先核验 T01。读 data-model-v1.md 全文及 API DTO 的对应字段。
实现 24 个逻辑实体、唯一键、同租户复合外键、必要索引、状态检查约束及可回放迁移。向量维度采用 T01 锁定配置；Prisma 不支持的部分使用该版本支持的迁移扩展，不创建第二份真相 schema。
包含 clarificationPending、AI version/lease/attempts、独立内部备注、bootstrap 短期加密收据，以及创建组织前的全局幂等收据。种子仅用合成客户和独立测试组织。
验收：空库迁移/重复种子、跨组织 FK、消息及业务请求唯一性、公开 seq 不受备注影响。提供实际数据库断言，不用 db push 代替迁移验收。
~~~

### T03 账号、企业、成员与邀请

~~~text
执行开发任务 T03，先核验 T02。实现 A001—A014、A069 与 P01/P02，按后续页面需求提供邀请列表。
实现注册登录退出、后台不透明 Cookie、显式组织上下文、admin/agent、组织创建、邀请预览/一次接受/撤销/列表、最后管理员保护。邀请链接 token 用 fragment，不在列表恢复原 token；后台写入落实约定的 Origin/CSRF 组合。
验证多标签选择企业不串上下文、并发邀请消费仅一次、创建组织响应丢失重试不重复建组织、停用成员请求失效、DTO 不含密码或令牌。T08 尚未实现的停用会话补偿明确留待 T08，不标整个 AT16 完成。
~~~

### T04 跨站小窗身份与接入

~~~text
执行开发任务 T04，先核验 T03。按 API A018—A021/A024、页面 P03 的身份合同实现加载脚本和 iframe 外壳。
父站点请求公开配置/bootstrap，以 publicKey+origin 分区保存访客令牌，通过校验 origin/source 的 postMessage 交给 iframe；后续聊天从 iframe origin 发起，服务端校验令牌绑定站点。成员 Cookie 与访客 Bearer 分离。
实现 10 分钟加密 bootstrap 收据和同键恢复；访客表仅存 hash，密钥留在服务端。实现可选姓名/邮箱/语言更新及版本控制。
验收真实两个 origin、禁止 origin、禁第三方 Cookie、存储不可用、bootstrap 响应丢失与过期、邮箱冒认历史负例。不能仅用同域 demo 证明跨站恢复成功。
~~~

### T05 会话与消息事务

~~~text
执行开发任务 T05，先核验 T02/T04。实现 A027—A029/A038—A040 与 canonical Message。
首消息与会话原子创建；message、递增 seq、outbox 及需要的 AI task 在同事务保存。先授权，再按发送者与 clientMessageId 判重；同键不同正文返回 409。历史提供稳定水位与 latest/before/after 模式。
验收同 ID 并发、成功后 ACK 丢失、关闭后的已成功请求重试、数据库失败不确认成功、公开历史不含备注、无空会话统计。当前任务只创建 AI 任务事实，不假装模型链路已实现。
~~~

### T06 outbox、Socket 与 HTTP 恢复

~~~text
执行开发任务 T06，先核验 T05。读 API 第 4 节及技术方案的一致性/故障部分。
实现 outbox 领取/重投、Socket subscribe/send/提交后 ACK、授权广播及队列投递。HTTP 与 Socket 使用 T05 同一个发送 service；队列只带定位 ID。广播接收者依据当前资源权限重新计算。
验证保存后进程退出、发布后未标记、重复事件、ACK 丢失、广播先于 ACK、Redis 不可用时 HTTP 保存与补拉。业务效果只能一次，投递本身允许重复；不能以 Redis 锁替代数据库唯一约束。
~~~

### T07 前端消息状态与连接

~~~text
执行开发任务 T07，先核验 T06。读 frontend.md、API 第 4 节、pages-v1.md 公共规则。
实现单一 API/Socket 客户端、身份上下文、连接销毁、消息 pending/sent/failed 归并和草稿隔离。首次订阅获得水位后读最新 50 条，上翻历史与实时补拉独立；使用 lastContiguousSeq，不能按最大 seq 跳过缺口。
ACK 超时先查询或用同 ID 重试；HTTP 降级只运行一个恢复循环。验证乱序/重复、断线重连、切企业、退出与迟到回调；允许重复文字，不按正文去重。新事件不覆盖人工草稿。
~~~

### T08 交接、认领、成员在线与关闭

~~~text
执行开发任务 T08，先核验 T03/T05/T06。实现 A015—A017/A030—A037 及统一会话状态服务。
完成转人工、原子认领、管理员指派、转交、关闭/人工重开、成员停用补偿和 AI 关闭后的状态变更。在线由 availability+有效 Socket/HTTP 心跳共同判断；HTTP 可首次注册，不依赖 Socket 曾成功连接。
在组织/会话锁与版本校验内使旧 AI 任务失效，首次转接和首次人工回复事实只能写一次。验证双人认领、停用/转交后发送拒绝、超时心跳、重复转接、关闭不改工单；重开及开 AI 均不能把已有人工会话自动转回 AI。
~~~

# 后端开发规范

适用于 NestJS HTTP、Socket.IO、业务服务、Prisma、worker 与内部 AI 调用。业务写入只在 NestJS 的受权服务中完成。

## 模块和输入输出

- Controller/Gateway 仅负责协议、DTO 和身份上下文；service 负责授权、事务和状态迁移；repository/Prisma 负责查询。事件处理器不直接绕过 service 写表。
- 输入 DTO 使用运行时校验和字段允许列表，输出 DTO 与数据库实体分离；错误、分页和 ID 格式遵循 [contracts.md](contracts.md)。
- packages/shared 只放公共 Schema、类型和纯转换，不能反向依赖 server 实现或导出数据库连接。
- 事务中不等待 Socket ACK、模型响应或 Redis 网络调用；避免把用户连接生命周期与数据库事务绑定。

## 身份、租户与访客

- 客服与管理员使用服务端会话；组织选择必须验证成员关系，角色和会话分配权限在 service 再校验。
- 访客使用服务端签发、过期可撤销的会话凭据，只能访问绑定客户的授权会话。前端传入 customerId、conversationId 或 room 名称不能作为身份或授权依据。
- Socket 握手、加入房间和每条写入事件都校验身份与资源权限；连接存活不等于权限永久有效。成员移除、注销、会话失效时撤销房间订阅。
- 所有业务查询、唯一约束、缓存、outbox、任务及日志关联范围包含租户。记录不可见时返回约定的 404，不泄漏其他租户资源是否存在。
- 客户端不得指定 senderId、server seq、assignedAgentId 等受控字段实现冒充；分配操作走独立受权用例。
- 角色与资源可见范围遵循 [V1 PRD](prd-v1.md)：客服可认领未分配等待会话，其余写入要求当前负责人资格；管理员回复前也先接管。最后管理员保护、成员停用和权限撤销在服务端执行。
- 内部备注及知识来源使用受限 DTO 和广播范围；访客的消息接口不能通过改字段读取备注或模型输入。邮箱只作联系信息，不能作为历史访问凭据。

## 消息可靠性

1. 认证并校验发送权限，按 contracts 的幂等作用域查询已有请求。
2. 在一个数据库事务内分配会话序号，保存 message 与待广播/待处理 outbox。唯一约束防止并发重复写入。
3. 提交后才 ACK；重复请求返回原 canonical message，内容不一致返回冲突。
4. outbox 投递器可重复发布，消费者按消息 ID/任务幂等键去重。标记已投递不表示客户端一定看到，仍需历史补拉。
5. 第一版可先支持单业务实例；扩展多实例时再接入对应广播适配器，并测试断线、跨实例与 Redis 中断。

具体锁顺序、首次消息/收据/outbox 的事务边界见 [数据模型](data-model-v1.md#6-事务与并发操作)，API 与 Socket 共同行为见 [API 详细设计](api-v1.md)。不得持有数据库锁等待模型或网络。

Socket.IO 保证已抵达事件的顺序，但默认不替应用提供持久化补偿；本项目必须以数据库序号和重连查询补齐，见 [官方交付保证](https://socket.io/docs/v4/delivery-guarantees/)。

## AI 任务与工单

- AI 任务记录与业务触发记录同事务持久化，Redis 暂时不可用由 outbox 后续投递。taskId、组织、输入快照版本和 Prompt 版本可追踪。
- 自动回答发送前同时校验最新输入、AI 开关、知识版本及启用状态、会话仍为 AI 接待。校验与保存必须与转接、接管、关闭的状态变更有一致的并发裁决，不能先检查后无条件写入。
- 服务端生成 AI 发送身份和幂等键；模型、浏览器及重复任务不能授权自身发送。新输入/转接/知识变更使旧候选失效，历史已保存回答不重写。
- 自动接待的等待上限从客户消息保存计时，包含排队；队列故障时仍由业务服务可恢复地推进人工状态，不能依赖故障队列中的任务才能降级。迟到投递不得重新启动过期自动接待。
- 任务重试复用同一业务 taskId；结果落库有唯一约束和条件更新，不能因为 worker 重启重复添加建议/摘要。
- AI 服务响应无效或输入版本已过期时，按 contracts 记录 failed/superseded，不覆盖新的摘要；客服本地编辑由前端 draftRevision 保护。超过任务时限的迟到结果不得把失败任务改为成功。
- 工单状态迁移、分配及会话关闭在 service 校验，使用 version 做乐观并发控制。AI 不拥有工单状态机入口。
- 认领采用条件更新，成功后只有一名负责人；转交撤销原负责人的写权限。会话关闭与工单解决独立，无隐式联动；待客户回复由人工明确设置。

## 数据与运维

Prisma schema 与 migration 各有唯一位置；测试迁移的空库初始化和已有数据升级，部署不以 db push 代替版本迁移。分页查询按组织、会话和 seq 建索引，禁用无界全表聊天历史加载。

后台浏览器使用同源 HttpOnly 会话 Cookie，生产 Secure；HTTP 写入验证 Origin/CSRF，Socket 握手校验 Origin 和会话。网站访客使用独立 Bearer，父站点第一方存储与 iframe 受限握手恢复身份，不依赖第三方 Cookie；bootstrap 的 origin 与聊天 iframe origin 区分，详见 [API A021](api-v1.md#3-http-接口清单)。Python 内部接口使用服务身份，不转发客户凭据。

连接配置沿用用户或项目确认方式，不自动引入 config.local.json。数据库与模型凭据保留在服务端；日志记录 requestId、messageId、conversationId、taskId、耗时与错误码，默认不输出整段聊天内容及凭据。AI 服务边界见 [agent.md](agent.md)。

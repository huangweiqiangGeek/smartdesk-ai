# 质量与交付规范

本规范用于任务实施、代码评审、测试和交付。T01 已建立本地检查脚本，具体命令与实际证据见 [本地开发](local-development.md)。CI 与业务集成/E2E 仍待对应任务实现；下文定义各阶段验证职责。

## 开发方式

1. 按 AGENTS 索引读取任务相关规范，写清可观察行为、影响模块和验收条件。
2. 先确定 Schema/事件契约再开发两端；修复缺陷时先建立可复现条件，禁止用静态假数据代替已实现声明。
3. 变更保持局部，真实复用出现后才抽象；不要把客服项目扩展成另一个通用 Agent 平台。
4. 新依赖先核对官方文档、兼容版本及必要性。TS 使用 pnpm 与锁文件；Python 选一种依赖管理方式并锁版本。
5. TypeScript strict、ESLint/Prettier；Python 类型注解、Ruff 和一种类型检查器。初始化后在项目 README 记录实际命令与执行目录。

## 验证分层

| 层级 | 验证目标 | 工具目标 |
| --- | --- | --- |
| 单元 | DTO、状态机、幂等输入摘要、前端消息合并、AI 输出校验 | TS Vitest；Python Pytest |
| 集成 | PostgreSQL 事务/唯一约束、Prisma 迁移、outbox、BullMQ 重试、内部服务认证 | 真实隔离数据库/Redis及可控故障注入 |
| 契约 | HTTP 与 Socket 共用行为、ACK/错误、版本与 cursor、内部 AI Schema | Schema 与消费者断言 |
| E2E | 配置知识、AI 接待、交接停发、双窗口人工聊天、内部辅助及工单 | Playwright |
| AI 评测 | 知识回答与依据、应转则转、翻译保真、摘要事实、草稿可用性、注入抵抗 | PRD 第 12 节固定版本评测集 |

## 关键验收用例

- 租户 A 不能读取 B 的客户、消息、工单和 AI 结果；访客不能冒充客服、枚举其他会话或自行加入房间。
- HTTP 和 Socket 同时发送同一个 clientMessageId，只落一条消息；同键不同内容返回冲突。
- 数据库提交成功但 ACK 丢失、广播先到、断线与重连、历史加载与实时事件交错，都只展示一次并可补齐序号。
- 组织切换、成员移除、登出、会话关闭后，旧连接不能继续接收或发送受限消息。
- Redis/BullMQ/AI 服务故障时，已提交消息可查询且人工回复可用；延迟投递可恢复，不谎报跨实例实时通知已经到达。
- worker 在结果保存前后崩溃并重试，不产生重复建议/摘要；过期结果不覆盖新草稿。
- AI 建议生成不会自动触发 message 创建；客服编辑后发送的内容是实际人工确认版本。
- 自动回答只在 AI 接待且输入/知识有效时保存；转人工、接管、关闭、知识停用和新输入与生成并发时，过期候选不发送。
- FAQ/文本编辑后重新准备与启用，试问不创建业务会话；租户隔离覆盖知识和来源，内部备注不进入访客消息流或对客草稿上下文。
- 无客服在线仍保存留言；AI 关闭/超时/队列失败进入人工路径，重启后迟到任务不恢复自动接待；最后管理员与停用成员的重新分配有覆盖。
- 工单同时编辑触发版本冲突，不出现丢失更新；非法状态迁移被拒绝。
- 工单待客户回复、解决与重开符合状态规则；会话结束不解决工单。指标用可手算样本核对，无响应不能记为零秒。

权限泄漏、重复业务消息、转人工后自动发送、未经客服确认外发人工草稿为硬失败。产品验收编号与 AI 初始门槛见 [V1 PRD](prd-v1.md) 第 12 节；AI 文本质量按固定样本量和版本建立基线，不以主观“看起来可以”作为唯一验收；真实模型验证和 mock 故障测试分别报告。

## 交付与部署

工程初始化时建立 lint、typecheck、unit/integration、build 和 E2E 脚本。改哪个边界就运行对应检查，公共契约变更同时验证所有消费者。纯文档修改检查引用与语义，不新增只镜像正文的单元测试。

37 项需求、AT01—AT27 与 26 项开发任务的追溯见 [开发任务与验收清单](development-tasks-v1.md)。执行入口见 [Codex 提示词](codex-prompts-v1.md)；任务依赖完成和实际证据齐备后才能标完成，文档交付不能替代未来代码验收。

Docker Compose 固定镜像版本，健康检查区分存活和就绪；先迁移再启动应用，验证空库和升级路径。AI 服务不对公网暴露。演示数据与真实数据分开，退出测试后清理仅由本次任务启动的进程。

交付报告必须包含实际命令/退出码、验收范围、未验证项与已知限制；在线部署、真实模型和本地集成不能混称。提交、推送和发布遵循用户授权与 Profile 现有 Git 配置。规范变更同步 docs 正文、AGENTS 路由和 Profile 引用。

# 前端开发规范

适用于客服工作台与客户聊天入口。前端展示可理解的消息状态，服务端确认才决定消息是否已保存。

T07 的统一客户端、实际装配、内存草稿策略和验收入口见 [前端连接开发与验收](frontend-development.md)；完整聊天页面仍归 T09/T10。

## 组件与类型

- 使用 Vue Composition API、`script setup`、TypeScript strict；页面编排、组件展示、composable 管理 HTTP/Socket 生命周期。
- HTTP 客户端、错误映射和 Socket 事件编解码集中维护。公共类型来自后端 OpenAPI/共享事件 Schema，不从 Prisma 数据模型直接导入。
- 局部状态保留在组件；跨页面会话状态才使用共享 store。禁止用 any 掩盖未确认数据结构。
- 客户入口与客服工作台分别装配可见功能；前端隐藏按钮只是体验，不能作为权限边界。

## SSR 与连接生命周期

- SSR 的用户数据按请求隔离，不使用模块级可变单例存储会话。首屏查询避免 SSR 和 mounted 重复请求。
- Socket 只在客户端登录/访客会话建立后连接；每个活动身份复用受控连接，不在每个聊天组件重复建立 socket。
- 登出、组织切换和会话失效时解绑事件、断开旧身份连接并清空相应缓存；重连时重新认证。页面离开清理监听器，切会话不会累积重复消费。
- `runtimeConfig.public` 仅含公开配置；完整服务端配置不能通过 useState 或 SSR payload 暴露。参见 [Nuxt runtime config](https://nuxt.com/docs/4.x/guide/going-further/runtime-config)。

## 聊天状态与补偿

- 发送前生成稳定 clientMessageId 并保留待发送内容；HTTP/Socket 重试都复用该 ID，不制造新消息。
- 乐观消息显示 pending；数据库 ACK 或消息查询确认后才显示 sent；明确拒绝显示 failed。ACK 超时表示结果未知，先查询/补拉或以同 ID 重试，不能断言消息未保存。
- 广播可能先于 ACK 到达；以 server messageId 和 clientMessageId 合并为同一条，不以文本或时间猜测去重。
- 初始历史加载与实时事件可能交错，先监听并暂存事件，再合并历史和连续 seq，缺口补拉；不能用最大已见 seq 跳过缺失消息。
- 断网保留草稿与未确认请求状态，并提示是否恢复。页面刷新后不能把未确认请求冒充已发送；持久化草稿策略在实现时明确，不把消息正文长期写入未经隔离的共享缓存。
- sent 仅表示服务端保存，不显示成已读。状态枚举及 ACK 格式见 [contracts.md](contracts.md)。

## AI 接待、辅助与可访问性

- 小窗按服务端状态显示 AI 接待、等待人工、人工处理中、已结束；AI 与人工身份明确。转人工必须收到服务端成功结果才显示完成，失败保留重试入口。
- 自动 AI 回答通过 canonical Message 展示，不能将 AI 任务流或草稿通知直接当作客户消息。等待人工后停止生成动画，不展示尚未保存的迟到候选。
- 知识库分别展示业务启停状态与准备状态；修改已启用资料后提示重新准备与启用。来源详情只在授权后台显示。
- 原文与译文分别展示，原文不被覆盖；翻译失败仍能阅读原文和人工回复。
- 回复建议先进入可编辑草稿，必须经客服点击发送；不要因异步建议到达覆盖客服正在编辑的内容。
- AI 结果绑定输入快照；有更新消息后标识旧建议/旧摘要。失败可重试，不能无限自动刷新。
- 富文本与客户消息按不可信内容渲染，限制链接协议和原始 HTML。禁止把内网错误、服务凭据或其他客户信息展示到访客入口。
- 会话、工单和表单覆盖加载、空、失败、权限不足及提交中状态；键盘可达、焦点清晰、消息更新提示不抢占输入焦点。
